# Reference anchors (docs/0065 D8)

Taste by selection, not vocabulary: the owner cannot articulate fixes
but can pick what looks right. These are the owner-picked exemplars
every new UI surface composes toward. Each surface **names its anchor
in the PR body**; deviations are noted there, never smuggled. The
pinned gpui-component `story` crate gallery (60+ live widget panels in
the house visual register) stays the always-on **secondary anchor**
for widget-level composition — no pick needed, it ships with the
toolchain.

## The picks

| Anchor | Note |
|---|---|
| [Linear](https://linear.app/) | Data-table restraint, typography hierarchy without size-shouting, muted chrome + a single accent — the register for usage/analytics tables, badges, and any list-dense surface. |
| [Things 3](https://culturedcode.com/things/) | Whitespace rhythm, list elegance, effortless light/dark twins — the register for the home page cards and the overall spacing feel of the app. |
| [Zed](https://zed.dev/) | gpui-native composition: panel chrome, theme tokens, exactly what our rendering stack expresses well. **Provisional pick** ("maybe", per the owner) — kept as the dev-tool register for the GitHub module views; drop it if it never earns its place. |

Links over screenshots (D8: "whatever is easiest") — all verified live
at pick time. Anchors are compositional references, not pixel targets:
surfaces borrow rhythm, hierarchy, and restraint, not layouts.
