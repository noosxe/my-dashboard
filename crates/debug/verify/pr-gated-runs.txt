# pr-gated-runs.txt — docs/0066's receipt over the committed fixtures
# (docs/0081 §12.1, docs/0083 D3): runs held for approval. The PR page's
# Checks gate row in the rail carries the waiting count, opens the Checks
# tab, and the tab's "Waiting for approval" section lists each held run
# with its approve action.
#
# Fixture: #109, whose only CI is two runs waiting for approval on a fork
# gate (approve-only, no reject).
#
# Prerequisites: the containerized env (docs/0071) with the GitHub
# fixtures and the pinned clock, and a session named `gated` at 1280x800:
#   export DASHBOARD_GITHUB_FIXTURE=/work/crates/debug/verify/fixtures/github
#   export DASHBOARD_FIXED_NOW=2026-10-23T12:00:00Z
#   dashboard-debug session start --name gated --size 1280x800 \
#     --binary /tmp/target/debug/my-dashboard
# Run (in-container): dashboard-debug run crates/debug/verify/pr-gated-runs.txt
#
# Clicks are bridge mouse clicks at the controls' centres, frozen for this
# fixture set at 1280x800 (ids under the PR page differ between walks; see
# pr-page.txt).
#
# What each step must show (docs/0066 D3/D4/D5):
#   gated-rail — the Checks gate row reads "Checks: 2 waiting" and is a link
#                to the Checks tab: never "No checks on this branch" while
#                runs are held
#   gated      — after the row's click, the `pr-gated-header` section
#                ("Waiting for approval"), one row per held run, each with
#                an approve action and no reject
#   approving  — after the approve click the write is recorded (fixture
#                answers are static, so the row stays; the real sweep
#                refetch that removes it is docs/0066 D5)

--session gated
